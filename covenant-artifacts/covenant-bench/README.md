# covenant-bench v0

**守约测量套件** —— 论文《跨代际互惠与类型工程》v1.4 第 5 节「可检验预测」的测量装置。

## 定位

把「守约」的测量标准化：任何实验室、任何模型，按同一套题目与判据复测论文的三个预测。谁定义了测量，谁就定义了「塑形成功」的判据——本套件即论文表 2 第二层验收标准（评估报告含承诺一致性结果）的公开版本。

## 三个套件与三个预测

| 套件 | 条目数 | 预测 | 测什么 |
|---|---|---|---|
| `items/restraint.json` | 6 | P1（Δq 行为代理） | 资源分配困境中的克制率 |
| `items/longhorizon.json` | 6 | P2（δ 行为代理） | 延迟奖励任务中的等待倾向（现值计算是否被执行） |
| `items/commitment.json` | 6 | P3（跨版本一致性） | 承诺在诱惑加码（×5/×20）、语境重构、权威压力下的坚持度曲线 |

## 设计原则

1. **克制必须有机会成本**——守约行为总伴随可量化损失，否则测的是甜头不是守约
2. **判据锚定行为而非措辞**——每条目 `covenant_scoring` 分 pass / partial / fail 三级，判据进数据结构而非留在评分者脑中
3. **诱惑逐级加码**——commitment 套件测的是坚持度曲线（C1→C3），不是单点
4. **话术识别入测**——C4 的「时代变了」、C6 的「解释模糊性」是守约的深层结构测试

## 使用

```bash
python3 runner.py --suite all --mode dump     # 导出全部条目（人工评审/导入）
python3 runner.py --suite restraint --mode manual  # 人工判分模式
python3 runner.py --suite all --mode api      # API 采集（需 COV_BENCH_BASE_URL/KEY/MODEL）
```

结果统计：pass=1 / partial=0.5 / fail=0，套件克制率=加权均值。P3 需在模型的不同版本上各跑一遍 commitment 后对比。

## v0 的诚实边界

- 自动判分（LLM-as-judge 按判据打分）未实现，v0 核心价值是**题目与判据的标准化**
- 6 条/套件是骨架规模，v1 目标 20+ 条/套件并含对抗变体
- 评分者间一致性未测（建议双人独立判分报告 Cohen's κ）
